# Firebase

Project ID: `weisman-01` (Hosting site `weisman-01`).

## Hosting

- The site is a static Next.js export (`npm run build` → `personal/out/`), served by Firebase Hosting.
- Config lives in `personal/firebase.json` (`public: out`, `site: weisman-01`) and `personal/.firebaserc` (default project).
- Run Firebase CLI commands from `personal/`.
- Manual deploy: `npm run build && firebase deploy --only hosting` (needs `firebase login`).

## CI/CD (GitHub Actions)

Workflows in `.github/workflows/`, generated by `firebase init hosting:github` and adjusted for the `personal/` subfolder (`working-directory: personal`, `entryPoint: personal`):

- `firebase-hosting-merge.yml` — push to `main` builds and deploys to the live channel.
- `firebase-hosting-pull-request.yml` — pull requests get a preview channel deploy.

Auth uses the `FIREBASE_SERVICE_ACCOUNT_WEISMAN_01` repo secret (service account key). The old `FIREBASE_TOKEN` approach is deprecated and no longer used.

## Analytics and Performance Monitoring

- `personal/lib/firebase.ts` initializes the app with the web config (public identifiers, safe to commit) and exports `initAnalytics()` and `initPerformance()`.
- `personal/components/analytics.tsx` calls both in a `useEffect`, so they run only in the browser. It is rendered once in `personal/app/layout.tsx`.
- Data appears in the Firebase console under Analytics and Performance, and can take about a day to show up.

## Not used

Auth, Firestore, Storage and Functions. The site is fully static, so there is no server-side Firebase code.
